# R04 — end-of-day valuation from saved moving-average events (partial)

The existing `inventory_cost_events` table seeds each stock pair at moving-average activation and records `tanggal`, `qty_delta`, `value_delta`, `qty_after`, and `value_after` for later average-valued movements. The existing monthly closing function itself selects the latest event per warehouse/item through its cutoff. This candidate exposes that same source for an arbitrary end-of-day date **on or after activation**, with branch subtotals, all-selected total, detail, and recorded source numbers. Branch ledger drilldowns appear only when the separate Buku Besar module is allowed; their balances are not calculated or claimed reconciled by this report. It never reads current FIFO layers as if historical, and it does not create a journal or change costing settings.

The reader retrieves every selected warehouse event through the date with exact-count pagination. Numeric cost and quantity columns are selected as PostgreSQL text so JSON parsing cannot round them before Decimal arithmetic. It rejects missing activation/initial or middle events when quantity/value continuity fails, keeps a value unavailable when the monetary chain becomes unknown, and keeps branch/total unavailable if any selected detail is unavailable. A first non-activation event may start from zero for a new warehouse/item after activation; that does not prove any earlier FIFO cost. For **today's** position it compares event end quantities to current stock in both directions, so a nonzero stock row without an event or a nonzero event without a stock row fails closed. It includes inactive warehouse/item records and labels negative qty. A branch summary is the exact Decimal sum of all its detail rows, independent of page size. The date and activation cutoff use WIB. For an earlier date, current stock cannot prove whether a missing stream existed then or started later; no report can reconstruct a vanished historical stream from today's balance.

The `column::text` read syntax follows [PostgREST's casting documentation](https://docs.postgrest.org/en/v12/references/api/tables_views.html#casting-columns); no view or new API permission is needed.
The report rejects source numbers outside its 80-digit arithmetic envelope rather than silently rounding them.

Historical branch ownership is still limited: `warehouses.branch_id` is mutable under existing RLS, while warehouse audit (migration `20261022083000`) is metadata only, began after some history, and is not readable by FINANCE. The report explicitly labels branch attribution as the **current warehouse assignment**. This is not evidence that the warehouse belonged to that branch on the selected historical date. No new privilege, RLS policy, trigger, or migration is introduced to manufacture that evidence.

FIFO and dates before activation remain unavailable. Migration `0074_kartu_stok.sql` inserted a synthetic opening stock movement using then-current `items.buy_price`, not a proven acquisition-cost history, so arbitrary historical FIFO valuation would be fictitious. Activating average today does not make prior FIFO history available. Saved monthly snapshots and the separate R04 GL comparison PR #210 remain complementary; this branch does not modify that PR.

Fixture tests use fictional branches, warehouses, items, activation seeds and later movements, including exact multi-row branch sums, post-cutoff exclusion, negative/incomplete source handling, denied branch, missing seed/middle event, read error/count failure, and 1,201 event rows. No target data, financial posting, production settings, or production security changes were made. R04 remains partial pending authoritative FIFO source, historical branch attribution, target reconciliation, and deferred field UAT.
