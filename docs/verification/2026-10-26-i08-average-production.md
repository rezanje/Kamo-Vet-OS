# I08 moving-average production candidate

Scope: same-branch recipe and ad hoc jobs in the existing `moving_average` mode. Source-warehouse material issues use `stock_out_fifo`'s moving-average cost while physical FIFO takes remain auditable. Output receipts use `stock_in_fifo` and the existing 12-decimal weighted-average valuation/events. The exact material cost remains the WIP document amount and transfers to the output movement and production journals. Source snapshots, idempotent receipts and retry behavior are unchanged.

The migration patches the two existing `SECURITY DEFINER` RPC bodies after checking known source anchors. It takes the existing costing-method advisory lock before reading the mode. It compares source cost events with frozen WIP and checks output valuation events against the production inventory journal plus any **existing** negative-stock variance journal. A discrepancy of at least Rp0.005 aborts the stage atomically. It preserves function identity, ACL, search path and RLS; it adds no table, role, policy, account or grant. Review and approval are required before any target migration apply. No target migration or transaction was applied in this worker.

Technical evidence from a disposable network-none PostgreSQL 17.6 database with 267 repository migrations and fictional auth/storage: recipe issue used average cost 0.359375 instead of first-layer FIFO 0.3125; ad hoc materials in two source warehouses carried 2.875 + 5.2 = 8.075 to output; WIP cleared; output weighted average and existing variance events reconciled. A large existing output quantity causing >Rp0.005 rounding drift rejected and left the job running without an output or finish receipt. A distorted material event, failed start/finish journal, duplicate retry and two-session concurrent start/finish were also checked. The original FIFO production SQL/races and concurrent activation guard remain passing. No hosted simulation or live accounting assertion is claimed.

Still open under I08: cross-branch expense context/interbranch allocation and any non-material expense policy. No account or variance treatment for those cases is inferred here. Rollout must inspect target function definitions and costing configuration before applying the migration; the provenance guard will reject an unexpected definition.
