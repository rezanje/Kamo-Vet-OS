# I08 atomic recipe-production prerequisite

The existing recipe-based production flow performs material issues, WIP journals, completion receipts and final journals as separate HTTP writes. Its `nilai_bahan` and per-material `hpp` columns also round exact FIFO cost to cents. Before adding ad-hoc/multi-warehouse production, reproduce those failure boundaries and make this existing financial core atomic.

Keep the current recipe, one warehouse, one output SKU, actual FIFO cost and WIP 1302 model. New start/completion RPCs validate active OWNER/ADMIN, current module/branch/warehouse/period, finite positive quantities and eligible materials, then commit source, stock/layers, exact WIP/finished journals and private receipts together. Durable request identity and source snapshots support lost-response recovery; unchanged retry returns one receipt, changed retry rejects. Legacy jobs without authoritative new proof require reconciliation rather than invented valuation. Existing table ACL/RLS are not widened. New receipt-backed sources reject stale direct mutations.

Widen future cost storage to numeric without restating historical rounded rows. If cost/quantity has no finite single unit-price representation, output valuation uses a documented high-precision base layer and a final decimal-quantity quantum residual layer so output layer cost exactly equals consumed WIP. Test the allocation; no silent write-down or weakened balance checks.

Use RED action/SQL precision failures, focused app and isolated PostgreSQL17 tests, real two-session retries/start-vs-sale/completion races and forced journal/audit rollback; then one final aggregate check after stable. No target migration or main retry. The only planned production page edits are request identity/recovery fields, outside catalog loaders already covered by PR113; preserve that candidate's loader changes when integrating. I08 ad-hoc/multi-source/output-vs-expense-branch workflow remains separate, not claimed complete.
