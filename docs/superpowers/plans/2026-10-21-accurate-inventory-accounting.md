# Accurate initial inventory → branch GL

Base: main `d6d9c70`. Scope is Accurate initial inventory, separate from PR69 stock document corrections and PR70 monetary opening corrections.

`post_accurate_initial_stock` originally writes quantities, original FIFO lots, stock moves and import status without GL. Branch balance readers select the exact journal branch. A global opening may already include inventory, so neither the current remaining FIFO nor an assumed Rp133m gap is a safe accounting entry.

New imports stop after master import and persistent stock-batch preview. An active OWNER uses `/keuangan/persediaan-awal`, explicitly selects a detail credit-normal EKUITAS account and records the accounting decision. Server preview contains source hash, exact selected/excluded rows, original amount, accounts, branch, warehouse and as-of date. Posting rechecks the entire preview under locks and commits original stock, FIFO, moves, a balanced debit 1301 / credit equity journal on the import branch and date, and immutable receipt together. No default equity or revenue assumption is made. Non-equity counterpart decisions require a separate reviewed accounting plan.

An existing posted batch is report-only. Its original basis is **not** inferred from remaining FIFO: compare posted import rows, original `qty_in × unit_cost`, source move quantities/costs, exact item/lot multisets, and remaining FIFO separately. The report includes other inventory GL and global opening entries across branches/dates, including gross lines rather than a possibly misleading net balance. Any other inventory/global opening GL blocks new automatic posting. Existing source drift, closed/missing period configuration, stale previews, changed warehouse/branch, invalid amounts/accounts/actor or prior stock history fail closed. This is intentionally conservative when normal inventory GL is already running.

Posting identity is the import batch; exact original actor/account/reason/review retries recover its one stored result. Conflicting retries fail. The former stock-only RPC now raises a review instruction; its implementation is private to the atomic bridge. Protect bridge import provenance, original FIFO basis and stock moves, receipt and journal; FIFO `qty_left` consumption remains allowed. After bridge posting, the generic global opening cannot insert 1301 or relabel an existing 1301 journal into an opening. No general opening replacement/deletion path is restored.

Historical repair remains a separate, approved operation: verify complete original rows/lots/moves; establish the original accounting cut-off and branch allocation; reconcile original inventory GL, HPP since cut-off, transfers and any opening/global entries; document counterpart and closed-period policy; preview balanced branch-specific entries with batch provenance and duplicate checks. The current report deliberately has no historical apply endpoint. Do not upload again, reset stock, post the remaining valuation, or copy an unexplained total into 1301.

Implementation and validation: native isolated PostgreSQL migration/fixtures, failure rollback and waiting-session races; application action/form tests, baseline comparison, types, lint and production build. No production DB write, migration, reset, merge or deploy is authorized by this change.
