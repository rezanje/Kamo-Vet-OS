## Batch 2 — Attendance correctness and approved schedule changes

**Likely files:** staff attendance actions/UI, attendance/location helpers/tests, schedule actions, request actions/UI, reports. Schema changes only after tracing existing structures.

- [ ] Add a failing regression for check-in at 20:00 day D and check-out at 08:00 day D+1. Fix session association in shared flow; retain date/time sufficient for payroll duration.
- [ ] Cover duplicate check-in/out, stale open sessions, unauthorized employee, month boundary, and Jakarta timezone. Never auto-close silently or fabricate worked hours.
- [ ] Present outstanding sessions for authorized correction with old/new values, actor and reason; do not leave staff permanently blocked by unhandled prior overtime.
- [ ] Add schedule-change request and approval. Approval and schedule update must commit atomically; two-person swaps update both schedules or neither. Handle concurrent approvals and changed schedules.
- [ ] Calculate attendance from approved effective schedule. Approved move from 07:00 to 08:00 produces no lateness at 08:00.
- [ ] Preserve configurable location checking; test wrong branch/outside radius and clear handling for missing branch coordinates/GPS. Do not add continuous tracking.
- [ ] Enhance daily/monthly recap and export using existing reports: days, worked time, lateness count/duration, leave and overtime; flag inconsistent records before payroll.

**Acceptance:** overnight attendance stays one correct session; approved swaps stop erroneous deductions; corrections are traceable; unauthorized cross-branch access fails in separate test environment.
