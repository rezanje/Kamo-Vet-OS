## Delivered behavior

- Active OWNER only can preview/correct monetary openings on the account ledger's **Koreksi saldo awal** screen. Server and database enforce this independently; delegated all-branch capability does not authorize ADMIN/FINANCE/STAFF/DOCTOR correction. Operational branch context, inactive accounts/branches/COA and owner-equity account checks remain authoritative.
- Resolves a unique proven `cash-account-opening` or the selected monetary line of the existing general `saldo-awal`. Incomplete, duplicate, future/infinite, voided/revised or inconsistent source journals fail closed. A missing opening is supported as the existing creation flow's zero at account creation, except where a different global opening date makes that date ambiguous: that case requires evidence matching before correction.
- Immutable original journals remain posted. Each correction reverses only the previous cash/equity amount and replaces it on the same opening date. Noncash opening lines, physical inventory, transfers, invoices and later transactions are preserved. No income/expense account is posted. Zero replacements remain correctable. Reports sum originals plus signed reversals/replacements exactly once.
- Preview shows old/new opening, delta, complete account ledger balance before/after (including already posted future-dated entries), reason and both balanced journal pairs. Changes to inputs invalidate the UI preview; server compares the full reviewed evidence again. A posted writer or competing correction invalidates stale evidence.
- Closed periods, retained closing journals and relevant active bank reconciliations block changes. Ambiguous legacy reconciliation records without an account/code conservatively block bank corrections. The correction serializes with the existing reconciliation ledger snapshot lock, so reconciliation either blocks a later correction or captures its corrected balance.
- Actor/key-scoped saved results, exact-payload checks and unique account revisions prevent duplicate posting. Recovery waits for an in-flight matching operation and reads its saved result without reposting. Unconfirmed responses retain the durable draft. All journals, audit and request records commit/roll back together.
- Existing opening creation now posts atomically, rejects repeated cash rows/double openings, and retains its prior role restrictions. The former destructive general opening replace/delete path is rejected, including stale server-action clients. Account creation validates cents/bounds before persistence; an uncertain posting response keeps the account mapping for inspection rather than deleting possibly posted evidence. Account-master creation itself remains the existing multi-step workflow; it was not redesigned.
