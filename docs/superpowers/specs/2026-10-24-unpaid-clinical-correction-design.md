Safety design: new SECURITY INVOKER correction RPC and triggers, session/RLS client only, active profile plus existing clinic module rules plus operational branch access. Append-only server-authored before/after row images, actor/time/reason/request key and transaction ID prove each correction. The submitted-record trigger permits only a nested exact before/after update backed by the current transaction receipt; ordinary UPDATE/DELETE remains denied. No client-set session flag or disabled trigger. Audit images remain under clinical RLS; general activity audit retains metadata-only behavior. Exact retry returns the same record; altered payload/key reuse fails; later edits use a new key and revision.

Navigation: Edit sits in Hasil pemeriksaan and points to the same visit with explicit record ID. Existing RekamForm renders saved clinical values and read-only downstream sections. Its correction draft is isolated by user/record/revision and distinct from initial-exam drafts. Batal clears only that correction draft and returns to the result. Save stays on the same visit and displays current values. Paid/invoiced or inaccessible record never renders correction mode and the database independently rejects stale/tampered saves.
